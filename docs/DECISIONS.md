# 결정 기록 (DECISIONS)

### 2026-11-04 · 게임·인터랙티브 + 다중화면·연동형 및 [B] 형태 선정
최대 30인 이상의 실시간 물리 동기화와 웹소켓 방 통신이 필수적이므로 단일 HTML이 아닌 [B] 빌드 도구 및 클라이언트-서버 분리형 구조를 채택함.
HTML5 Canvas 2D 기반의 경량 렌더러와 Node.js Socket.io 서버로 학교 PC 및 모바일 브라우저에서도 지연 없이 원활히 구동되도록 설계함.

### 2026-11-04 · 실시간 접속 인원수 비례 동적 스케일링(Dynamic Scaling) 규칙 채택
2명이 플레이할 때 30명용 기믹이 나와 진행이 불가능해지는 현상을 방지하기 위해, 현재 룸 접속자 수(N명)에 따라 퍼즐 조건(열쇠 높이, 블록 무게, 발판 스위치 수)을 자동으로 계산·적용하도록 규칙화함.

### 2026-11-06 · GitHub 및 Vercel 배포 최적화: WebRTC P2P (PeerJS) 아키텍처 전환
Vercel은 상시 WebSocket 서버(Node.js 상주 프로세스)를 호스팅할 수 없는 서버리스 플랫폼이므로, 백엔드 서버 없이 브라우저 간 초저지연 직접 통신이 가능한 WebRTC DataChannel (PeerJS) 아키텍처로 전환함.
이로써 구글 드라이브 내 `node_modules` 생성 충돌을 원천 해결하고, 외부 서버 비용 0원으로 Vercel 정적 호스팅에 원클릭 배포할 수 있는 초경량 고성능 구조를 확립함. 교내망 CDN 차단을 방지하기 위해 `peerjs.min.js`를 프로젝트 내부에 직접 번들함.

### 2026-11-06 · 전체 5단계 작업 완료 및 배포 패키징
WebRTC 룸 시스템, 듀얼 조작계(PC/모바일), 플레이어 스택킹 탑 쌓기, 인원수 비례 동적 기믹(열쇠, 발판 스위치, 밀기 상자, 문), Stage 1~3 레벨 디자인, 무음소 신디사이저 사운드 매니저 구현을 완료하고 `공유용/` 및 `README.md` 배포 가이드를 완성함.

### 2026-11-06 · 교실 프로젝터 QR 입장 및 모바일 듀얼 플레이 모드 도입
교사가 교실 칠판에 방을 열면 자동으로 선명한 고해상도 QR 코드가 생성되어 학생 스마트폰 카메라 스캔으로 즉시 방 코드가 입력되어 접속되도록 구현함.
